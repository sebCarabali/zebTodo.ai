## Context carried in from PRD/architecture

- Product is a medication-coordination app for family caregivers (working title, "ZebTodo" is the project codename, not the product name).
- Platform: MAUI mobile (iOS/Android) as primary surface, Blazor web as complementary panel. Exact móvil/web feature split is explicitly open (PRD Open Question #6) — owned by this UX session.
- Web (Blazor) already has page stubs anticipated: AdherenceDashboard.razor, CaregiverManagement.razor.
- Mobile (MAUI) already has view stubs anticipated: Calendario, Confirmación de Toma, Adherencia, Gestión de Cuidadores, Testamento Digital.
- Real-time via SignalR — UI must communicate "live" state for cross-confirmations and calendar changes.
- Personas: Paciente, Cuidador Principal, Cuidador (solo alertas), Cuidador de Respaldo, Contacto de Emergencia.
- 3 PRD journeys to mirror: UJ-1 (Marta confirma toma → notificación cruzada), UJ-2 (Don Carlos no responde → escalada completa), UJ-3 (Don Carlos configura círculo + testamento digital).
- Open items affecting UX: umbral de "patrón preocupante" (default propuesto 3 días, sin validar); mecanismo de aprobación de transferencia del Testamento Digital.
- Hard constraint: UI must communicate that el Protocolo de Última Línea no es un servicio de emergencias garantizado.
- Pilot scope: Colombia (Habeas Data / Ley 1581 de 2012) — privacy-sensitive context.

## Decisions made in this UX session

- **Modo de trabajo:** Fast path elegido por el usuario — se redactan ambos spines completos con tags `[ASSUMPTION]` en los huecos, sin herramientas creativas (paletas, wireframes) en esta pasada.
- **Stakes:** Regulado — confirmado por el usuario dado el dominio de salud + datos sensibles + usuarios potencialmente vulnerables (adultos mayores). Implica rigor extra en accesibilidad, lenguaje de consentimiento, y honestidad sobre límites del Protocolo de Última Línea.
- **Split móvil/web (resuelve PRD Open Question #6):** Confirmado por el usuario. Móvil (MAUI) es la superficie completa — calendario, confirmación de toma, adherencia, gestión de cuidadores, testamento digital. Web (Blazor) es un panel complementario de solo lectura + gestión ligera para cuidadores a distancia — adherencia + gestión de cuidadores únicamente. Ninguna confirmación de toma desde web.
- **Marca y tono:** El usuario delegó la propuesta de identidad visual/tono a UX. Se redacta `[ASSUMPTION]`: cálido pero confiable, no clínico/frío, sin alarmismo salvo en estados de escalada real, sin gamificación (explícitamente fuera de alcance en el PRD).
- **Nombre de marca: "Juntos".** Resuelto en esta sesión. Se propusieron 4 opciones (Vela, Círculo, Juntos, Pulso) coherentes con calidez/círculo familiar/sin tono de vigilancia; el usuario eligió "Juntos" porque pone el acento en la coordinación familiar — el problema real que resuelve el producto — por encima de la medicación en sí. Reemplaza el placeholder "ZebTodo" (que sigue siendo solo el nombre en código del repo) en `DESIGN.md` y `EXPERIENCE.md`.
